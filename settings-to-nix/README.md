# Settings to Nix

Configure Noctalia entirely in its settings window and still keep the configuration
declarative: this plugin writes your settings to a Nix file that your NixOS, Home
Manager or hjem configuration uses as Noctalia's config. After you have rebuilt, it
cleans the applied values out of Noctalia's GUI layer, so nothing gets lost and
nothing is kept twice.

> [!IMPORTANT]
> **This plugin only writes a `.nix` file. It never builds, switches or changes your
> system configuration.** Your system uses the new settings only after you
> 1. include the file in your configuration once (see [Setup](#setup)), and
> 2. rebuild yourself after exporting, for example with
>    `sudo nixos-rebuild switch --flake .` or `home-manager switch`.
>
> With flakes, the file has to be inside your config repository and tracked by git
> (`git add`), or Nix cannot see it.

## Plugin

| Field | Value |
| --- | --- |
| ID | `dmopp/settings-to-nix` |
| Entries | Shortcut: `export`; panel: `panel`; service: `service` |

## Requirements

- `nix`: the generated file is meant for a NixOS, Home Manager or hjem configuration.
  `nix-instantiate` on `PATH` is used to check the file before it replaces the old
  one; without it the check is skipped.
- The `noctalia` command on `PATH`, for importing your current config, the clean-up
  step and the rebuild reminder (they read your config with
  `noctalia config export merged`).

## How it works

Noctalia reads its configuration in two layers:

1. `~/.config/noctalia/*.toml`: the config. On NixOS it is generated by Nix and
   read-only; Noctalia never writes to it.
2. `~/.local/state/noctalia/settings.toml` (`$XDG_STATE_HOME`/`$NOCTALIA_STATE_HOME`
   are honored): everything you change in the settings window. This layer wins.

Changes made in the GUI only ever land in layer 2, outside of Nix. The plugin closes
the loop:

```text
GUI ──writes──▶ settings.toml ──export──▶ gui-settings.nix ──your rebuild──▶ config.toml
                      ▲                                                          │
                      └──────────── clean-up removes what config.toml now has ◀──┘
```

- **Export** writes the settings to the Nix file (default
  `~/.config/noctalia/gui-settings.nix`, see [Setup](#setup) for where it should go).
- **Import current config** adds your whole existing config once, so the Nix file can
  become your complete Noctalia config.
- The plugin keeps a record of every value it exported. The Nix file therefore keeps
  a value after the clean-up has removed it from `settings.toml`, and a later GUI
  change overwrites it.
- **Clean-up** removes a value from `settings.toml` only when your rebuilt config
  already holds the same value. Before a rebuild it removes nothing.

Runtime values that are not settings are left out by default: `config_version` and
the wallpaper paths Noctalia rewrites on every wallpaper change
(`wallpaper.last.path`, `wallpaper.default.path`, `wallpaper.monitors.*.path`).

## Usage

### Setup

The recommended setup makes the generated file your **complete** Noctalia config: you
set everything in the GUI, and Nix only links the file. If you keep a hand-written
`config.toml` or `programs.noctalia.settings` today, it is taken over in step 3 and
can be deleted afterwards.

1. **Install and enable** the plugin, and add its control-center tile
   (see [Where the buttons are](#where-the-buttons-are)).
2. **Set the target file inside your config repository.** Open **Settings → Plugins**,
   click the gear on the **Settings to Nix** row and set **Target Nix file**, for
   example `/etc/nixos/noctalia/gui-settings.nix` or
   `~/nixos-config/noctalia/gui-settings.nix`. The directory must be writable by your
   user.
3. **Import your current config.** Open the panel and click **Import current config**
   once. The Nix file now contains your whole current config, with your GUI changes on
   top. Check the file before you continue.
4. **Track it in git** (flakes only):

   ```sh
   git -C /etc/nixos add noctalia/gui-settings.nix
   ```

5. **Point Noctalia's config at the file** and remove whatever produced the config
   before. Pick the variant that matches your setup:

   **Plain NixOS** (no user-level module):

   ```nix
   { pkgs, ... }:
   let
     noctaliaConfig = (pkgs.formats.toml { }).generate "noctalia-config.toml"
       (import ./noctalia/gui-settings.nix);
   in
   {
     environment.etc."xdg/noctalia/config.toml".source = noctaliaConfig;

     # ~/.config/noctalia/config.toml -> /etc/xdg/noctalia/config.toml
     systemd.user.tmpfiles.users.alice.rules = [
       "L+ %h/.config/noctalia/config.toml - - - - /etc/xdg/noctalia/config.toml"
     ];

     # The symlink itself does not change on a switch, so tell a running Noctalia.
     system.userActivationScripts.noctalia-config-reload = ''
       ${pkgs.procps}/bin/pgrep -u "$USER" -x noctalia >/dev/null \
         && /run/current-system/sw/bin/noctalia msg config-reload >/dev/null 2>&1 || true
     '';
   }
   ```

   **Home Manager** (Noctalia's `homeModules.default`):

   ```nix
   {
     programs.noctalia = {
       enable = true;
       settings = import ./noctalia/gui-settings.nix;
     };
   }
   ```

   **hjem** (Noctalia's `hjemModules.default`):

   ```nix
   {
     hjem.users.alice.programs.noctalia = {
       enable = true;
       settings = import ./noctalia/gui-settings.nix;
     };
   }
   ```

6. **Rebuild** (`sudo nixos-rebuild switch`, `home-manager switch`, ...).
7. **Clean up.** Open the panel: under **3. Clean up** it now says how many values your
   config provides. Click **I have rebuilt: clean up settings.toml**, then
   **Confirm**. From now on `settings.toml` only holds what you changed since the
   last rebuild.

> [!TIP]
> **Keeping settings of your own next to the GUI ones.** If you would rather write
> part of the config by hand, skip step 3 and merge the GUI file on top of your own
> settings, for example
> `settings = lib.recursiveUpdate { /* your settings */ } (import ./noctalia/gui-settings.nix);`.

### Where the buttons are

After enabling the plugin you will not see a button anywhere yet. Noctalia does not
add plugin shortcuts to the control center on its own. There are three ways to use
it; pick one.

> [!NOTE]
> The control center's Home tab holds **at most six shortcuts**, and the default set
> already uses all six (`wifi`, `bluetooth`, `caffeine`, `nightlight`,
> `notification`, `power_profile`). To add the tile you have to **remove another
> shortcut first**; until then the **+** button stays disabled and nothing tells you
> why. If you do not want to give one up, use the panel (B) or automatic export (C).

**A. Control-center tile (recommended)**

1. Open **Settings → Control Center** and expand **Home**. The **Home shortcuts** list
   holds at most **six** shortcuts. When it shows `6/6`, the **+** button is disabled:
   remove one shortcut with its **✕** first.
2. In the dropdown, choose **Settings to Nix**. The dropdown shows the plugin's name;
   the tile itself is labeled **Export to Nix**. Then click **+**.
3. The tile (a snowflake) now appears at the bottom of the control center's Home tab:
   - **Click** opens the panel.
   - **Right-click** exports directly, without opening the panel.
   - The tile is highlighted while the GUI has changes that are not in the Nix file
     yet, and reads **Export to Nix (changed)**.

The same in TOML:

```toml
[[control_center.shortcuts]]
type = "dmopp/settings-to-nix:export"
```

**B. Panel only, e.g. on a compositor key binding**

```sh
noctalia msg panel-toggle dmopp/settings-to-nix:panel
```

**C. No button at all.** Turn on **Export automatically** in the plugin settings.
Every GUI change is then written to the Nix file within a few seconds. The panel is
still needed once for the import and for the clean-up.

The panel has three sections:

1. **Export:** how many settings the Nix file holds, the target path, **Export to Nix**
   and **Import current config**.
2. **Rebuild:** a reminder that you rebuild yourself.
3. **Clean up:** how many values your rebuilt config already provides, the clean-up
   button (two clicks: the first one turns into **Confirm: remove N values**) and a
   button to compare again.

### Everyday use

1. Change settings in the GUI as usual.
2. Export: right-click the tile, use the panel, or let **Export automatically** do it.
3. Rebuild when it suits you. Until then the GUI values stay active from
   `settings.toml`, so nothing is lost if you never rebuild.
4. After the rebuild, clean up in the panel.

Optional reminders (off by default) notify you once when GUI changes have not been
exported for some hours, and when exported settings are still not in your built
config some days after the export.

The generated file looks like this:

```nix
{
  bar.Top.capsule_opacity = 0.35;
  shell.greeter_sync.auto_sync = true;
  theme = {
    mode = "dark";
    source = "wallpaper";
  };
}
```

## Settings

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `target_path` | `file` | `~/.config/noctalia/gui-settings.nix` | File the settings are written to. It is overwritten on every export. With flakes, point it inside your config repository. |
| `auto_export` | `bool` | `false` | Export whenever `settings.toml` changes (checked every 2 seconds) instead of only on demand. |
| `notify` | `bool` | `true` | Notification after a manual export or clean-up. Errors are always shown. |
| `remind_export_hours` | `int` | `0` | Notify once when GUI changes have not been exported for this many hours (0–168, 0 = off). Not used with `auto_export`. |
| `remind_rebuild_days` | `int` | `0` | Notify once when exported settings are still not in your built config this many days after the export (0–30, 0 = off). Checked every 10 minutes. |
| `exclude` | `string_list` | see [How it works](#how-it-works) | Dotted paths left out of the export; `*` matches one level (advanced). |
| `validate` | `bool` | `true` | Check the generated file with `nix-instantiate --parse` before replacing the target (advanced). |

## IPC

```sh
# Export now (same as right-clicking the tile)
noctalia msg plugin dmopp/settings-to-nix:service all export

# Add the whole current config to the Nix file (same as "Import current config")
noctalia msg plugin dmopp/settings-to-nix:service all import

# Count the GUI values your config already provides (read-only)
noctalia msg plugin dmopp/settings-to-nix:service all check

# Remove those values from settings.toml (no confirmation, meant for scripts)
noctalia msg plugin dmopp/settings-to-nix:service all cleanup

# Forget everything recorded for the target and export settings.toml as it is now
noctalia msg plugin dmopp/settings-to-nix:service all reset
```

`export` fits well in a rebuild alias, before the rebuild runs.

## Notes

- **Nothing is dropped silently.** If the target file already exists but the plugin
  has no record of it (for example after you changed the target to a file you wrote
  yourself), the export refuses to overwrite it. Run **Import current config** first,
  or `reset` to start from the GUI settings alone.
- **Removing a value:** a setting that disappears from `settings.toml` (for example
  after resetting it in the GUI) stays in the Nix file with its last exported value. Set the value you want
  in the GUI instead, or edit the record in the plugin data dir (see below) and export
  again. `reset` empties the record.
- **Files written:** the target file (via `<target>.tmp` and a rename). In the plugin
  data dir (`~/.local/state/noctalia/plugins/data/dmopp/settings-to-nix/`): the record
  of exported values (`exported-*.toml`), the reminder state (`reminders.json`) and an
  empty `empty-state/` dir. On clean-up only: `settings.toml`, after a copy of the
  previous version is saved as `settings.toml.bak` in the plugin data dir. Noctalia
  reloads `settings.toml` on its own.
- **Processes:** `nix-instantiate --parse <target>.tmp` (export, when `validate` is on)
  and `env NOCTALIA_STATE_HOME=<empty dir> noctalia config export merged` (import,
  clean-up, check and the rebuild reminder). The latter reads your config without the
  GUI layer, with Noctalia's own merge rules and `[include]`s. Nothing else is run,
  and there is no network access.
- TOML values Nix cannot express (`inf`, `nan`) are left out; dates are exported as
  strings.
- The plugin reads Noctalia's GUI layer itself (with its own TOML reader), so it does
  not need `remarshal`, `yj` or similar.
